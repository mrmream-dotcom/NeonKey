Set up a virtual machine for any ISO

TutorialPractical ITIntermediate· 9 min read

A virtual machine (VM) is a whole computer running in a window on your computer. It has its own operating system, its own files and its own “hardware”, all borrowed from the machine you’re sitting at. This guide works for any installer disc image (ISO), whether that’s Linux, Windows or something more unusual, and for whichever VM software you pick. Menu names differ between apps, but the steps are the same.

Why use a VM?

The short answer: you get a spare computer you can break, wipe and rebuild in minutes, without touching the one you rely on. That’s useful for a lot of everyday jobs:

  • Try an operating system first. Test-drive a Linux distribution, or a new Windows version, before you install it for real.
  • Test software and updates safely. See what an app or update does inside the VM before it goes anywhere near your work machine.
  • Build a learning lab. Practice networking, servers and security on machines you’re allowed to break. This is how a lot of IT people learn.
  • Keep old software running. An app that only works on an older operating system can live on in its own VM.
  • Undo almost anything. Snapshots (covered below) let you save the VM’s exact state and roll back to it in seconds.

A VM isn’t a perfect wall between it and your real computer, so don’t treat it as a safe place to open something you know is dangerous. For everyday testing and learning, it’s a big step up from experimenting on your main machine.

What you’ll need

  • A 64-bit computer. 8 GB of memory (RAM) is a workable minimum, and 16 GB is comfortable, since the VM borrows from what you have.
  • Free disk space, roughly 30 to 70 GB per VM depending on the operating system
  • VM software (called a hypervisor). Options are in the next section.
  • The installer ISO for the operating system you want, downloaded from its official site
  • A license for the operating system, if it needs one (Windows does)
  • About 45 minutes, most of it waiting on the installer

Pick your VM software

All of these do the job. Pick by what your computer runs:

Your computerGood choicesNotes
WindowsVirtualBox, VMware Workstation Pro, Hyper-VHyper-V comes with Windows Pro, Enterprise and Education. Turn it on under “Turn Windows features on or off.”
Mac with Apple silicon (M-series)UTM, VMware Fusion, Parallels, VirtualBoxRuns Arm versions of operating systems well (see the note below).
Mac with IntelVirtualBox, VMware Fusion, UTMRuns most standard 64-bit ISOs.
Linuxvirt-manager or GNOME Boxes (both use KVM), VirtualBoxKVM is built into the Linux kernel.

VirtualBox, UTM and the KVM tools are free. VMware Workstation Pro and Fusion are free for personal use. Parallels is paid. Download from the vendor’s own site, not a mirror.

Our suggestion if you’re unsure: VirtualBox on Windows or Linux, and UTM on an Apple silicon Mac. Both are free, and the steps below map onto them cleanly.

The Apple silicon catch. A Mac with an M-series chip runs Arm software. It runs Arm builds of operating systems (for example, an “arm64” or “aarch64” Linux ISO, or Windows 11 on Arm) at full speed. A standard PC ISO (“x86_64”, “amd64” or “x64”) has to be emulated instead, which works in some apps but is very slow. Grab the Arm download when one is offered.

Step 1: Make sure virtualization is turned on

VM software leans on a feature built into your processor, called Intel VT-x or AMD-V (sometimes listed as “SVM Mode”). It’s on by default on most modern computers, but not all.

  • Windows: open Task Manager, go to Performance, select CPU, and look for “Virtualization: Enabled.”
  • Mac: nothing to do. It’s always available.
  • Linux: run egrep -c '(vmx|svm)' /proc/cpuinfo in a terminal. Any number above zero means you’re set.

If it’s off, restart into your computer’s firmware settings (the BIOS or UEFI setup, usually by pressing F2, F10, F12 or Delete as it starts) and look for a virtualization option under the CPU or advanced settings. Turn it on, save and restart.

Step 2: Get the ISO and check it

An ISO is a single file holding everything on an installer disc. Download it from the operating system’s official site, and pick the version that matches your computer’s processor: x86_64 (also called amd64 or x64) for most PCs and Intel Macs, arm64 for Apple silicon.

Most download pages also publish a checksum: a long string of letters and numbers that acts as a fingerprint for the file. Checking it confirms the file arrived complete and hasn’t been tampered with. Run one of these on the downloaded file, then compare the result to the one on the download page:

  • Windows (PowerShell): Get-FileHash .\your-file.iso
  • Mac: shasum -a 256 your-file.iso
  • Linux: sha256sum your-file.iso

If the two don’t match exactly, delete the file and download it again.

Step 3: Create the VM

Open your VM software and choose New (or “Create a virtual machine”). The wizard asks for a few basics:

  1. A name. Something like “Test Lab” or the name of the operating system.
  2. The ISO. Point it at the file you downloaded.
  3. The operating system type. Many apps detect this from the ISO. If yours doesn’t, choose the closest match, or “Other” with the right 32-bit or 64-bit setting.

Some apps also offer an unattended or easy install that answers the installer’s questions for you. It’s handy, but turn it off for your first VM so you can see each step.

Step 4: Give it memory, processors and a disk

This is where most VM problems start, usually from giving the VM too little or too much. A simple rule: never give a VM more than half of your computer’s memory or processor cores, because your real computer still needs room to run.

Kind of systemMemoryProcessorsDisk
Lightweight Linux, or a server with no desktop2 GB1 to 225 GB
Desktop Linux (Ubuntu, Fedora, Mint and similar)4 GB230 to 40 GB
Windows 10 or 114 GB minimum, 8 GB if you can2 to 464 GB or more

These are good starting points, not hard rules. You can change memory and processors later with the VM switched off.

For the disk, choose dynamically allocated (also called “grow as needed” or thin provisioning). The file starts small and only grows as the VM stores things, so a 64 GB virtual disk doesn’t take 64 GB on day one.

Firmware: UEFI or BIOS. Modern operating systems expect UEFI, so use it unless the operating system is old. Windows 11 also requires Secure Boot and a TPM 2.0 chip. Current versions of VirtualBox, VMware and Hyper-V can provide a virtual TPM, so turn it on in the VM’s settings if the Windows installer says “This PC can’t run Windows 11.” In Hyper-V, pick Generation 2 when creating the VM; it’s the option that supports UEFI and Secure Boot.

Step 5: Choose a network mode

The VM gets a virtual network card, and you decide how it connects. The three common modes:

  • NAT (the default): the VM shares your computer’s internet connection and stays hidden from other devices on your network. Right for most uses.
  • Bridged: the VM joins your network as its own device, with its own address. Use it when other devices need to reach the VM, like a home server.
  • Host-only or internal: no internet. The VM can only talk to your computer or to other VMs. Use it for isolated testing.

When in doubt, leave it on NAT. Hyper-V names these differently: its “Default Switch” behaves like NAT, and an “External” switch behaves like bridged.

Step 6: Start it and install the operating system

Start the VM. It boots from the ISO just like a real computer booting from a USB stick, and the operating system’s normal installer appears. Follow it as you would on real hardware. When it asks which disk to install to, the virtual disk you created is the only one it can see, so erasing it is safe; your real drives aren’t visible from inside.

Clicking inside the VM window usually hands your mouse and keyboard to the VM. To get them back, press the release key: Right Ctrl in VirtualBox, Ctrl+Alt in VMware, and Ctrl+Alt+Left Arrow in Hyper-V. UTM and most Linux tools show theirs in the toolbar.

When the install finishes, remove the ISO from the VM’s virtual optical drive (most installers prompt you, or the VM settings have an “eject” option). Otherwise it can boot straight back into the installer instead of your new system.

Step 7: Install the guest tools

Once the operating system is running, install your VM software’s guest tools. They’re the drivers that make the VM pleasant to use: the screen resizes with the window, the mouse moves smoothly, copy and paste works between the VM and your computer, and graphics run faster.

  • VirtualBox: Guest Additions (Devices menu → Insert Guest Additions CD image)
  • VMware: VMware Tools, or the open-vm-tools package on Linux
  • Hyper-V: integration services, built into modern Windows and Linux
  • UTM, virt-manager and GNOME Boxes: the SPICE guest tools, plus qemu-guest-agent on Linux

Many Linux distributions already include these, so check before you install anything. Then run the operating system’s own updates, and restart.

Step 8: Take a snapshot

Now that you have a clean, updated system with guest tools, take a snapshot and name it something like “Clean install.” A snapshot saves the VM’s exact state, and restoring it rolls everything back in seconds. Take a new one before anything risky, like a big update or an app you’re unsure about.

Snapshots are an undo button, not a backup. They live alongside the VM’s own files, so if that disk fails, the snapshots go with it. To keep a real copy, use your software’s export feature (often an .ova file) and store it somewhere else. Also, a long chain of snapshots slows the VM down and eats disk space, so delete the ones you no longer need.

Common questions

It says “VT-x is disabled” or virtualization isn’t available. Go back to Step 1 and turn it on in the firmware settings. On Windows, VirtualBox and VMware can run alongside Hyper-V-based features (like WSL 2 or Memory integrity), but they may be slower when those are on.

The VM is very slow. Check that guest tools are installed, give it a bit more memory if your computer can spare it, and store the VM on an SSD rather than a spinning hard drive. On an Apple silicon Mac, make sure you used an Arm ISO.

It boots back into the installer every time. The ISO is still attached. Remove it from the VM’s virtual optical drive, then restart.

Do I need a separate Windows license for the VM? Yes. Windows in a VM needs its own license to activate. It will install and run without activation, with a watermark and some personalization settings locked, which is fine for testing.

Can I run more than one VM at once? Yes, as long as their memory adds up to comfortably less than your computer has. Two VMs with 4 GB each on a 16 GB computer is fine; four is pushing it.

Is a VM safe for opening suspicious files? Safer than your main computer, but not foolproof. If you do it, use host-only networking, turn off shared folders and the shared clipboard, take a snapshot first, and restore it straight after. For anything you know is malicious, leave it to a security professional.
