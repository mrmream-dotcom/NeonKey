Domain 3: Security Architecture

Study guideSecurity+Domain 3 of 5· 3 min read

Architecture is about designing things to be secure from the start: where systems live, how networks are split up, how data is protected, and how you keep running when something fails. It’s about 19% of SY0-801.

Exam version: these notes follow SY0-801 (V8), which CompTIA is set to launch on or around November 17, 2026. The older SY0-701 (V7) stays available in English until June 11, 2027 (Japanese, Portuguese, Spanish and Thai until August 13, 2027). Book the version you studied for.

What's different from SY0-701 in this domain: Weight rises slightly, from about 18% to about 19%. The four objectives keep the same order. Objective 3.2 now centers on Zero Trust architecture, Security Service Edge (SSE) and identity management (like gMSAs and privilege creep). Data protection (3.3) adds more data roles and the data management life cycle.

Architecture models

  • On-premises: you control everything and you’re responsible for everything. An air-gapped network has no connection to outside networks at all.
  • Cloud: deployment can be public, private, community or hybrid (a mix). Multicloud spreads work across more than one provider. Responsibility is shared: the provider secures what it runs, and you still own your users, data and settings.
  • Serverless: you supply code and the provider runs everything under it.
  • Microservices: an app split into small services that talk to each other, which means more connections to secure.
  • Segmentation: logical (separate networks in software, like VLANs) or physical (separate hardware).
  • Infrastructure as Code: environments defined in version-controlled files, so they’re repeatable and reviewable.
  • Weigh the trade-offs: availability, resilience, cost, scalability, ease of recovery, power and compute needs, usability, proprietary vs. open source, and data sovereignty (which country’s laws apply to the data).

Securing the infrastructure

Plan trust boundaries and allow only the traffic you need. Avoid one big flat network.

  • Placement and zones: put devices in the right security zone, so internet-facing servers are kept apart from internal systems. Keep the attack surface small.
  • Zero Trust architecture: check the user (authentication), the device (managed, healthy, in inventory), and the app before granting access, every time.
  • Secure access: VPNs and tunneling protect remote access. Out-of-band management keeps admin access on a separate path. Use secure file transfer and end-to-end encrypted messaging.
  • Security Service Edge (SSE): cloud-delivered security that sits between users and the apps they use.
  • Identity management: give accounts least privilege, use group managed service accounts (gMSAs) so service passwords rotate automatically, and watch for privilege creep (people collecting access they no longer need).
  • Failure modes: decide whether a failure should lock things down (fail closed) or keep them usable (fail open).

Data protection

Data needs protection in three states: at rest (stored), in transit (moving over a network), and in use (being processed in memory). It can be structured (like a database) or unstructured (like documents and email).

  • Classification labels data by sensitivity (public, confidential, restricted, secret, top secret, critical) and sets the handling rules, including marking and labeling.
  • Encryption and hashing protect data at rest and in transit.
  • Tokenization swaps a real value for a token that maps back to it in a protected vault.
  • Masking hides part of a value, like showing only the last four digits. De-identification removes what ties data to a person.
  • Roles: the owner is accountable, the custodian handles day-to-day protection, the steward looks after quality, and the controller decides how personal data is used.
  • Location: geofencing and data placement rules control where data can be stored or used.
  • Life cycle: creation, management, distribution, retention, and disposal.

Resilience and recovery

  • RTO: how fast a service must be back. RPO: how much data, measured in time, you can afford to lose. MTTR is the average time to repair. MTBF is the average time between failures.
  • Backups: set the scope and the retention. Immutable backups can’t be changed or deleted, which helps against ransomware. Test your restores, not just your backups.
  • Sites: a hot site is ready to go, a warm site is partly ready, and a cold site is just space and power.
  • Redundancy: load balancing, clustering, autoscaling and high availability. Platform diversity (more than one vendor or platform) avoids a single shared weakness.
  • Power: a UPS covers short outages, a generator covers long ones, and redundant power supplies and surge protectors protect the hardware.
  • Testing: failover tests, simulations and parallel processing show whether disaster recovery and business continuity plans actually work. Capacity planning makes sure you can handle the load.

Key terms

Try to define each term before you tap it.

IaaS

Provider handles physical infrastructure; customer commonly manages OS and workloads

PaaS

Provider also manages runtime/platform components; customer manages applications and data

SaaS

Provider operates application; customer configures access and protects appropriate data

Hybrid cloud

Mix of on-premises and cloud environments

Air-gapped network

Network with no connection to outside networks at all

Microservices

An app built from many small services, which adds connections to secure

Infrastructure as Code

Reproducible configuration defined through version-controlled code

Screened subnet (DMZ)

Isolated segment for internet-facing services, kept apart from the internal network

VPN

Encrypted tunnel across an untrusted network

Microsegmentation

Granular policies between workloads

SSE

Security Service Edge: cloud-delivered security between users and the apps they use

Out-of-band management

Admin access over a separate path from normal user traffic

Fail secure

A failure preserves restricted access even if usability is reduced

Data at rest

Information stored on disk or other media

Data in transit

Information moving over a network

Data in use

Information actively processed in memory

Tokenization

Substitutes sensitive data with a mapped surrogate token

Masking

Hides portions of sensitive information for display or testing

Classification

Labels data according to sensitivity and handling needs

RTO

Target maximum time to restore a service

RPO

Target maximum age of lost data after recovery

Full backup

Copies all selected data

Incremental backup

Copies changes since the most recent backup of any type

Differential backup

Copies changes since the most recent full backup

High availability

Design intended to minimize service interruption

3-2-1 backup rule

Three copies, two media types, one off-site copy

Data custodian

Party responsible for day-to-day handling of data under policy

Data sovereignty

Data is subject to the laws of the country where it is stored

gMSA

Group managed service account: a Windows service account with auto-rotating passwords

Privilege creep

Access that piles up as people change roles and nobody removes the old rights

Immutable backup

A backup that can't be changed or deleted, which helps against ransomware

Hot site

Backup site that is ready to take over right away

Quick self-check

5 practice questions in our own words. Pick an answer to see the explanation. Practice only: it doesn't predict exam results.

  1. A company runs its own operating system on a cloud virtual machine (IaaS). Who usually patches that guest OS? Obj. 3.1

    Show answer

    A. The cloud customer. In IaaS, the provider runs the physical hardware and virtualization layer. The customer manages the guest OS and everything on it.

  2. Where should a public-facing web server usually go? Obj. 3.2

    Show answer

    B. In a screened subnet (DMZ). A screened subnet separates internet-facing systems from sensitive internal networks, with tightly limited traffic between them.

  3. A sensitive field is replaced with a stand-in value, and the real value can only be looked up in a protected vault. What is this called? Obj. 3.3

    Show answer

    B. Tokenization. Tokenization swaps the real value for a token and keeps the mapping somewhere protected. Masking just hides part of the value on display.

  4. A system has an RPO of 10 minutes. What does that number describe? Obj. 3.4

    Show answer

    A. The most data (in time) you can afford to lose. RPO is about data loss measured in time. RTO is about how long recovery takes.

  5. You need backups that copy only what changed since the last FULL backup. Which type is that? Obj. 3.4

    Show answer

    B. Differential. Differential backups copy everything changed since the last full backup. Incremental backups copy changes since the last backup of any type.
