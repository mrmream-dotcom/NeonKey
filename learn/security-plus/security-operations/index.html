Domain 4: Security Operations

This is the biggest domain, at about 28% of SY0-701. It’s the day-to-day work: keeping systems hardened, knowing what you own, finding and fixing weaknesses, watching for trouble, managing who has access, and handling incidents.

Exam version: these notes follow SY0-701 (V7). CompTIA plans to launch SY0-801 (V8) on or around November 17, 2026. SY0-701 stays available in English until June 11, 2027. Book the version you studied for.

What changes in V8 for this domain: Weight is about 27%. CompTIA's V8 summary lists eight objectives here. 'Enhancing enterprise capabilities' (secure protocols, email security and similar) no longer appears as its own objective, and automation now mentions AI-assisted workflows.

Securing computing resources

Start every device from a secure baseline, then keep it there. Remove unused software, turn off unneeded services, patch, enable secure boot, and watch for configuration drift.

  • EDR spots suspicious behavior on endpoints and helps you investigate and contain it.
  • MDM/UEM enforces policy on phones and laptops.
  • Full-disk encryption protects a lost or stolen device.
  • Sandboxing runs untrusted code somewhere it can’t do harm.

Asset management

You can’t protect what you don’t know you have. Track assets through their whole life: purchase, inventory, owner, classification, maintenance, and disposal. Watch for shadow IT and forgotten devices. Sanitize media before it’s reused or thrown out, using overwriting, cryptographic erase, shredding or physical destruction, depending on the media.

Vulnerability management

It’s a loop: discover, scan, confirm, prioritize, fix or mitigate, then rescan.

  • CVSS scores how severe a flaw is technically, not your actual business risk. An exposed system with a known, actively used exploit can matter more than a higher score on an isolated lab box.
  • Authenticated scans log in to the system, so they see more.
  • False positives waste time. Confirm a finding before you act on it.
  • If you can’t fix something, document a risk exception and add compensating controls.

Alerting and monitoring

  • SIEM collects and correlates logs from many sources.
  • IDS detects and alerts. IPS sits inline and can block.
  • Tuning balances missed attacks (false negatives) against alert overload (false positives).
  • Use accurate time sync (NTP) and set clear log-retention rules, or you won’t be able to reconstruct what happened.

Enterprise security capabilities

Replace cleartext protocols with secure ones: SSH instead of Telnet, HTTPS/TLS instead of HTTP. For email:

  • SPF lists the servers allowed to send mail for your domain.
  • DKIM signs messages cryptographically.
  • DMARC tells receiving servers what to do with mail that fails those checks, and where to send reports.

DNSSEC proves DNS answers are genuine, but it does not encrypt them. File integrity monitoring flags unexpected changes to important files.

Identity and access management

  • Lifecycle: provision access, update it when roles change, and remove it quickly when it’s no longer needed.
  • MFA means factors from different categories: something you know, have, or are.
  • SSO and federation (SAML, OIDC) let one sign-in work across many apps.
  • RBAC grants access by role. ABAC decides based on attributes like department, device health and time.
  • PAM locks down and monitors admin accounts.

Automation and orchestration

Automation handles single repeatable tasks. Orchestration chains tools into a workflow (SOAR is the security version). They save time but can spread mistakes fast, so add guardrails: limited service accounts, approval steps before anything destructive, logging, and testing.

Incident response

The phases: preparation → detection and analysis → containment → eradication → recovery → lessons learned. Preserve evidence and keep a chain of custody before you make destructive changes. Practice with tabletop exercises.

Investigation data sources

Pick the source that answers your question:

  • Firewall and flow logs (NetFlow) show who talked to whom.
  • DNS logs show name lookups.
  • Authentication logs show sign-ins.
  • Endpoint telemetry shows processes and file changes.
  • Packet capture shows full traffic content, when it isn’t encrypted.

Line things up by timestamp, host and user, and hash evidence to show it hasn’t been altered.

Key terms

Try to define each term before you tap it.

EDR

MDM

Centralized mobile device policy and management

Secure baseline

Approved reference configuration for system settings

Application sandbox

Restricted execution environment

Disk encryption

Protects stored data if a device is stolen

Configuration drift

Deviation from a known approved configuration

Asset inventory

Record of devices, software, systems, and owners

Shadow IT

Unapproved technology in an organization

Data custodian

Party responsible for day-to-day handling of data under policy

End-of-life

End of vendor support or planned asset usability

Sanitization

Removing sensitive information before reuse or disposal

Cryptographic erase

Destroying encryption keys so encrypted data becomes inaccessible

CVSS

Standardized technical vulnerability severity scoring

False positive

Finding reported as present when it is not

Authenticated scan

Scanner uses credentials for deeper host visibility

Remediation

Fixing the root weakness, e.g. patching software

Risk exception

Documented acceptance or temporary exception

Rescan

Verifies that a mitigation or patch worked

SIEM

Centralizes and correlates security telemetry

IDS

Detects suspicious activity and generates alerts

IPS

Can actively block malicious network activity

False negative

Missed malicious activity

NetFlow

Summarized flow metadata rather than full packet payload

Syslog

Common mechanism for sending system and network logs

RBAC

Permission assignment based on organizational role

ABAC

Access decision based on attributes of identity, resource, action, and context

MFA

Two or more distinct authentication factor categories

SSO

One authentication session for multiple applications

PAM

Controls and monitors privileged access

Provisioning

Creation or granting of identities and privileges

Deprovisioning

Revocation of access when no longer needed

SSH

Encrypted remote terminal and administration

TLS

Protects communications in transit

SPF

Specifies permitted sending hosts for a mail domain

DKIM

Cryptographic signature for email authenticity/integrity

DMARC

Email authentication alignment and domain policy

DNSSEC

Authenticates DNS data using digital signatures

FIM

SOAR

Security orchestration, automation, and response tooling

Playbook

Documented sequence of incident or administrative actions

Operational steps for a specific repeatable procedure

API

Defined interface between software systems

Limit or approval mechanism to prevent damaging actions

Preparation

Plans, tools, contacts, and exercises before an incident

Containment

Limits ongoing damage or spread

Eradication

Removes attacker persistence or root cause

Recovery

Restores validated normal operations

Chain of custody

Documented tracking of who handled evidence and when

Post-incident review to improve defenses

PCAP

Record of logon events and identity decisions

Record of queries and resolutions

Process, file, registry, and host activity

Comparison of cryptographic digests for evidence integrity

Quick self-check

9 practice questions in our own words. Pick an answer to see the explanation. Practice only: it doesn't predict exam results.

  1. A laptop is stolen while powered off. What best protects the files stored on it? Obj. 4.1

    Show answer

    A. Full-disk encryption. Full-disk encryption keeps data at rest unreadable without the key. The other tools mostly help while the system is running.

  2. What is the most reliable way to find servers nobody is managing? Obj. 4.2

    Show answer

    A. Reconcile the asset inventory against network discovery. You can't secure what you don't know about. Comparing the inventory with what is actually on the network turns up unknown or orphaned systems.

  3. After patching a critical vulnerability, what confirms the fix actually worked? Obj. 4.3

    Show answer

    A. Rescanning or otherwise validating the system. A rescan or other validation checks that the original weakness is really gone.

  4. Which tool most directly correlates sign-in events and network events from many sources? Obj. 4.4

    Show answer

    A. SIEM. A SIEM gathers logs from many sources and correlates them, so related events show up together.

  5. A domain owner wants receiving mail servers to reject messages that fail SPF/DKIM alignment. Which record does that? Obj. 4.5

    Show answer

    A. DMARC. DMARC tells receivers how to handle mail that fails aligned SPF or DKIM checks, and where to send reports.

  6. Access depends on the user's department AND whether their device is compliant. Which access model fits best? Obj. 4.6

    Show answer

    A. ABAC. Attribute-based access control looks at attributes of the user, the resource, and the context (like device health) to make each decision.

  7. An automated workflow is about to disable hundreds of accounts after one noisy alert. What is the best safeguard? Obj. 4.7

    Show answer

    A. An approval gate and limits on scope. High-impact automated actions need guardrails: human approval, limits on how much they can change, and logging.

  8. The team isolates infected machines to stop the spread. Which incident response phase is this? Obj. 4.8

    Show answer

    A. Containment. Containment limits ongoing damage. Eradication (removing the cause) and recovery come after.

  9. You need a list of which internal hosts talked to an external IP, without full packet contents. What is the best source? Obj. 4.9

    Show answer

    A. NetFlow / flow logs. Flow data records who talked to whom, on which ports, and how much, without storing payloads. Packet capture works but is heavier than you need.
